## 1. One-Paragraph Status

FCLE Study Buddy is a **feature-complete, free-launch-beta web app** for Florida Civic Literacy Exam (FCLE) prep: a full 2,175-question bank across 4 domains, practice quizzes, 20-question diagnostic, stimulus-based practice, stats/analytics (premium-style), an AI tutor (RAG over KB), user accounts with **ORDER-faithful auth (registered-only, personal dashboard links, NO anonymous users, NO passwords)**, and a Template A (navy/gold light SaaS) UI applied consistently app-wide. It is the **first-launch product** of the Mu2 study-app ecosystem (FCLE → TEAS → NCLEX share ~90% code/harness). It runs **free in beta** via the `FCLE_FREE_LAUNCH` env flag (default ON — every user treated as premium). **Not yet deployed anywhere** (no droplet/domain) — that is the single biggest open item. Source is safely backed up in a private GitHub repo.

## 5. Auth, Plans & Paywall (per-app — no shared platform.db)

- **Each app owns its users table + local auth.** All platform-era code (`platform_id` column, `create_linked_user`, shared `platform.db`, PLATFORM_DB env wiring) was **removed** from all three apps (grep-verified zero refs) — do not reintroduce.
- **AUTH MODEL (Sep 6, 2026, ORDER-faithful — commit `ee5ef9f`): registered users ONLY. NO anonymous users, NO passwords.**
  - Register = email + display name. Account gets a 32-char `access_token` (`users.access_token`, unique index).
  - The **personal dashboard link is the login**: `/registered` handoff page shows `/?token=<access_token>` (Copy Link + Go to My Dashboard). Opening that link from any device auto-authenticates (session established, then session-first on later requests).
  - Login = email only: returning users re-receive their dashboard link on `/registered?r=1`.
  - Resolution order in `_get_current_user()`: session `user_id` (registered only — stale/anonymous ids dropped) → `?token=` query → `access_token` cookie.
  - `login_required` now redirects anonymous → `/login?next=...` instead of auto-creating a user. `/tutor`, `/tutor/chat`, `/tutor/history` are gated (were open).
  - Legacy password_hash/login helpers remain in db.py but are unused; do not reintroduce password flows.
  - **141 legacy anonymous rows + child data purged** (Mister K-approved) — dev DB is at 0 users; fresh signup creates the first registered user.
  - Email delivery of the link is env-gated (`SMTP_HOST/PORT/FROM/USER/PASS`) via `_try_email_dashboard_link()`; **no SMTP creds configured yet** — Mister K will add at deploy. On-screen link is the only channel until then.
- `users` has a `plan` column; `get_plan(user_id)` returns the plan string; `plan is_premium free_daily` exposed via context processor.
- Free tier design: 10 Q/day capped, enforced at quiz-start + answer routes → redirect `/pricing`. (All current users are registered; free-launch treats them as premium.)
- **`FCLE_FREE_LAUNCH` env flag (default ON):** treats every user as premium — unlimited questions, full analytics, no paywall redirects; pricing page shows launch-beta banner. **Flip to paid: set `FCLE_FREE_LAUNCH=0` and restart. No code changes.**
- Square billing deferred (checkout buttons inert; no subscriptions table). Phase 2 only if Mister K greenlights.
- DB portability warning (durable): TEAS PKs are INTEGER AUTOINCREMENT vs NCLEX TEXT uuid PKs; NCLEX `topic_mastery` columns diverge (`total_answered`/`total_correct` vs TEAS/FCLE `total_attempted`). v1 keeps per-app DBs.

## 7. UI/Design Conventions (LOCKED)

- **Template A = navy/gold light SaaS** (Mosaic-style). Mister K explicitly rejected mobile-app-looking UI — on larger screens pages must read as a proper **desktop web app**. Standing bar for ALL Mu2 web products.
- All six explored dashboard designs archived at `~/.nanobot/workspace/design-archive/teas-dashboard-templates/` for reuse.
- **Do not revert to legacy editorial styling** (cream #FAFAF7, forest #1B4332, burgundy #6B2737, serif Libre Baskerville headings). They exist in `legacy.css` only as a base layer for unstyled classes; `app.css` (Template A + skin) must win.
- **Load-order gotcha (durable):** app.css MUST load after legacy.css in base.html. If you add a `<style>` block to a template, it will beat app.css for equal-specificity rules — prefer app.css additions or `!important` sparingly. ID-level legacy rules (`#submit-btn`) need explicit overrides in app.css.
- Quiz submit button: navy at reduced opacity when disabled (intended), full navy when enabled.
- AI-slop tells to avoid: purple-pink gradients, glassmorphism, thick side-border rounded cards, Inter font, emoji icons.
- Real markdown pipe tables only in reports to Mister K (no line art).
